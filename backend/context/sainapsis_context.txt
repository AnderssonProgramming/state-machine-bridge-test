=== BRIDGE — PRODUCT ===
Bridge is an AI-powered engine that helps human-relationship-focused companies
sell more, manage customers smarter, and serve better.

The problem it solves: customer conversations are scattered across chats,
emails, and calls; CRMs go outdated; visibility disappears — hurting decisions,
service, and data security.

What Bridge does:
- One platform for calls, chats, and emails (no app-switching)
- Every interaction syncs automatically to the company CRM, with AI summaries
- AI Agents help teams work faster and serve better
- A "Smart Agent" analyzes all connected conversations and data sources to give
  real-time answers about customer interactions, satisfaction, and engagement

Key benefits: more productive teams, better decisions and higher sales, faster
support (less churn), and protected customer data.

Platform & technology:
- 100% cloud-based; available on Web, Windows, Mac, iOS, and Android
- Uses secure commercial and private Large Language Models (LLMs) to analyze
  conversations in real time
- No servers or complex setup required

Channels: WhatsApp (via a verified Meta Business account), email, and calls.

Authentication: Microsoft 365, Google G Suite, or username/password.

Industries served: banks and regulated financial entities, B2B companies, B2C
companies, law and advisory firms, life & health sciences, insurance, car
dealers, and home-construction companies — any business where employees manage
direct customer relationships (not pure call-center or transactional purchases).

Security: SOC 2 Type 2 certified, continuously monitored by Wiz, optional
private AWS deployments, public Trust Center via Drata.

Onboarding: (1) book a demo / contact, (2) account setup, (3) connect Meta
account + add users + launch, (4) optional internal-system integrations.

=== ORDER STATE MACHINE — THIS MVP ===
This system is a full-stack technical test: a state machine for an online order
processing system, built with a FastAPI backend on AWS Lambda and a React
frontend on Vercel.

Architecture:
- Backend: Python 3.13, FastAPI, Mangum (Lambda wrapper), Pydantic v2, AWS
  Lambda Powertools. Uses Repository Pattern (InMemory/DynamoDB) and Strategy
  Pattern for event handlers.
- Frontend: React 18, Vite, TypeScript, TailwindCSS. Includes a Dashboard,
  Order Creation, and Detail views with a live State Machine Diagram (React Flow).
- Infra: AWS (ALB/API Gateway, Lambda, DynamoDB) + Vercel (Frontend).
- CI/CD: GitHub Actions for testing (pytest, coverage), security (CodeQL), and
  deployment (AWS SAM).

States (11): Pending, OnHold, PendingPayment, Confirmed, Processing, Shipped,
Delivered, Returning, Returned, Refunded, Cancelled.

Transitions:
- (creation) -> Pending
- Pending -> OnHold (pendingBiometricalVerification)
- Pending -> PendingPayment (noVerificationNeeded)
- Pending -> Cancelled (paymentFailed / orderCancelled)
- OnHold -> PendingPayment (biometricalVerificationSuccessful)
- OnHold -> Cancelled (verificationFailed / orderCancelledByUser)
- PendingPayment -> Confirmed (paymentSuccessful)
- Confirmed -> Processing (preparingShipment)
- Processing -> Shipped (itemDispatched)
- Shipped -> Delivered (itemReceivedByCustomer)
- Shipped -> OnHold (deliveryIssue)
- Delivered -> Returning (returnInitiatedByCustomer)
- Returning -> Returned (itemReceivedBack)
- Returned -> Refunded (refundProcessed)
- Any state except Delivered/Returned/Refunded -> Cancelled (orderCancelledByUser)

Business rules:
- An order is created with productIds and amount, starting in Pending.
- An invalid event for the current state raises an error (HTTP 422).
- When paymentFailed occurs and the order amount is greater than 1000 USD, a
  support ticket is created for manual review in DynamoDB.
- A full event/transition history is stored alongside each order.
- The system is monitored via CloudWatch (Logs, Metrics, Tracing).
